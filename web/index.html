A private dataset from your own folders, for your private

Import a dataset

            
Bring in an adult dataset of your own: a folder (a read-only NAS mount too, never written to), a
              direct https link to an archive or file, or a Hugging Face dataset. Everything lands in a locked quarantine
              (private/quarantine); nothing in it can be cleaned, trained on or shown. Each item is then checked on
              this PC (the blocklist, minor safety for images and text, the age estimate, real people), and only what passed is
              released to private/datasets/<name>. Nothing is fetched until you confirm the source and its size.

owner_attests_consent = true
origin = "where it came from"
licence = "its licence"            # a link or a Hub dataset
url = "https://..."                # or: hf = "owner/name", or: folder = "/mnt/..."

                
A SOURCE.toml outside the folder must name the source it is for. Without one, nothing is read.

Loop a model (Avarta)
A copy of a Llama or Qwen3 model whose middle blocks run more than once with the same weights: it thinks deeper at the same size on disk. Each extra pass enters through a gate that starts closed, so the copy answers exactly as its base until it is trained (the gates train with the adapter). Convert carries the loop into the GGUF, and the Rust engine runs it.

          

          

              

                

                  

                

                  

                

                  

                

                  

                

                  

              

              

          

          

        

        

          
Upcycle to a mixture of experts
Turns a dense Llama or Qwen3 model (looped or not) into a real mixture of experts. Each block's feed-forward becomes several experts with a router that picks the best ones for each token. In training the experts share the base weights, and each one learns its own LoRA. At full width the copy starts out answering exactly like its base. With fine-grained experts (a neuron width, e.g. 120 experts of 1,024 neurons, top-5: 56B with 5B active) each expert is a slice of the feed-forward. A token then uses only some of the slices, so the copy starts close to its base but not equal to it. The dense-start check measures how close. When it is trained, export writes a qwen3moe GGUF that gives every expert its own weights, quantized as it is written.

Test a model
Runs the same fixed tests on each version of a model: the base, a looped copy at each pass count, every trained adapter. Code answers really run, with their tests, in a sandbox with time and memory limits and no network. Compare with an earlier report to see what got worse: a test is marked when the drop is larger than its noise.

Report

            

          
A suite is a JSON list of tests: held-out loss, code (HumanEval, MBPP, LiveCodeBench, Codeforces, Strandset-Rust), IndicQA-style questions, judge-scored answers, repeat (how much answers repeat themselves: distinct 2- and 3-grams, repeated 4-grams and sentences; lower is better) and samples (answers kept to read, beside the earlier report's). With a GGUF the answers come from the Rust engine (its attention cache and GPU graph); the loss tests still use the Workshop's model, and an adapter must already be merged into the GGUF. A judge on the GPUs this run takes cannot answer until it ends, so the run is refused: judge with a remote (assist) model or a CPU model. From a terminal: am2strata-workshop regress --model <hf-folder> --suite suite.json --passes 1,2 --engine-gguf model.gguf --engine-args "--devices cuda:0=14" --out <report-dir>.

          

        

        

          
Grade and train
In rounds: the model answers each prompt several times, every answer is graded (its code is run with the prompt's tests, or a judge model scores it), the best answer of each prompt is trained on, and the test suite runs on the new adapter. The adapter is kept only if no test got worse.

Abliterate a model
Finds the direction a model's hidden state takes before it refuses (from prompts it refuses and ordinary ones, one per line) and removes it from every matrix that writes that state. The copy answers instead of refusing; check its answers before you use it. Works on Llama and Qwen models, looped ones too.

Cluster

          
Workers
            
A master is the Prastara people and apps talk to; it keeps the keys, memory and queue. A
              worker is another Prastara that runs models for it: set "cluster": {"role": "worker"} in its run
              config. Workers on this network show here as "wants to join"; type the 6-digit code the worker shows to pair it.
              Nothing joins by itself. A chat goes to a worker when only the worker has its model, or when this PC is busy and
              a worker has the same model loaded and idle; the answer comes back through here.

            

          
Add one in the run config
            
"cluster": {"workers": {
  "pc2": {"url": "http://192.168.8.50:8000", "key": "env:PC2_KEY"}
}}

            
Workers can also be listed in the run config (used from the next start); the key is then the
              worker's own API key (or env:NAME). Pairing in the app gives each master a key of its own instead, and the worker's
              main key never leaves it. A worker paired in the app is reached over TLS 1.3, each machine checking the other's
              certificate as it was paired (the worker's port "tls_port", default its API port + 443, must be reachable from
              the master). Workers listed in the run config are plain HTTP with the key: across a network you do not trust,
              connect those machines through your own VPN (Tailscale, WireGuard).

        


        

          
Clients

          
API keys
            
A key for each app, user or machine that connects to this server. A key opens the model APIs
              (chat, pictures, speech) with the tools you give it, never these settings. It works as soon as it is made and
              stops as soon as it is revoked.

            
This server has no main API key, so anyone who reaches it can use it with
              no key at all. Set "api_key" in the run config for these keys to mean something.

Client profiles
            
Each client (a laptop, an agent, a phone app) gets its own API key with its own tools and memory. An
              agent that sends only the address and the key gets these tools with no other setting. They are set in the run
              config, and used from its next start.

            

          
Add one in the run config
            
"clients": {
  "laptop": {"key": "a-long-random-key", "tools": ["memory", "web", "image", "speech", "mcp:*"], "memory": "laptop",
             "limits": {"media_jobs_per_hour": 20, "max_image_size": "1024x1024",
                        "max_video_seconds": 10, "web_queries_per_turn": 5}},
  "default": {"tools": ["web"]}
}

            
Tools: memory, web, image, video, speech, music, browser, code (run_python in the sandbox), and MCP
              servers by name (mcp:files) or every address server (mcp:*). "default" is what the main key gets.

            Coding agents
            
Point a coding agent at this server or another Prastara, with the model you choose. In a terminal,
              am2strata agentrun <agent> runs it once (nothing of yours changes) and
              agent setup <agent> makes it the agent's default (its config is backed up; agent reset restores it).
              The key is read from AM2STRATA_API_KEY, never written into a file.
